Create a permanent subsystem:

## CAPABILITY EXTRACTION ENGINE — CEE

**Latent Capability**

**Blocked Capability**

**Recoverable Capability**

**Compounding Capability**

**Required Investment**

**Potential Return**

The system must distinguish:

### Existing
Already available.

### Recoverable
Available after optimisation.

### Composable
Created by joining existing capabilities.

### Emergent
Created by interaction between systems.

### Compound
Capability that increases the future capability of the system itself.

### Frontier
Capability that becomes possible only after crossing a meaningful threshold.

Prioritise opportunities that increase the system's **future ability to find additional opportunities**.

This is the compounding principle.

# III. COMPOUNDING EFFECT DETECTOR

Build a dedicated:

## COMPOUNDING EFFECT DETECTOR — CED

Never evaluate an improvement only by its immediate output.

Evaluate:

**ΔCapability₀**

and then:

**ΔCapability₁ caused by ΔCapability₀**

and then:

**ΔCapability₂ caused by ΔCapability₁**

Continue until marginal compounding becomes negligible or uncertainty becomes too high.

Search explicitly for:

**tool → better tool**

**data → better data acquisition**

**automation → more automation**

**revenue → more infrastructure**

**infrastructure → more computation**

**computation → better research**

**research → better capability**

**capability → more revenue**

This creates the:

## NORTH STAR COMPOUNDING LOOP

**CAPABILITY → OUTPUT → VALUE → CAPACITY → MORE CAPABILITY**

Optimise for sustainable compounding, not superficial activity.
